# nf-core/ezflux: Output

## Introduction

This document describes the output produced by the pipeline. Most of the plots are taken from the MultiQC report, which summarises results at the end of the pipeline.

The directories listed below will be created in the results directory after the pipeline has finished. All paths are relative to the top-level results directory.

## Pipeline overview

The pipeline is built using [Nextflow](https://www.nextflow.io/) and processes data using the following steps:

- [Preprocessing](#preprocessing) - sylph profiles of reads and micom taxonomy tables
- [Growth](#growth) - per sample and diet growth results
- [Merged results](#merged-results) - exchanges, rates and niche plots for all samples
- [MultiQC](#multiqc) - Aggregate report describing results and QC from the whole pipeline
- [Pipeline information](#pipeline-information) - Report metrics generated during the workflow execution

### Preprocessing

<details markdown="1">
<summary>Output files</summary>

- `preprocessing/sylph/`
  - `<sample>.tsv`: raw sylph profile of the (concatenated) reads (only for samples with reads).
- `preprocessing/annotation/`
  - `<sample>.annotated_abundances.csv`: species abundances (`placeholder,sample_id,species,abundance`) from sylph or BLAST.
  - `<sample>.blast_detailed.tsv`: best BLAST hit(s) per ASV of the sample (only with `--seqtab_input`).
- `preprocessing/asv/`
  - `seqtab.fasta`, `seqtab.counts.csv`: ASVs extracted from the wide table (ids `ASV1`...) and their long-format counts, all samples (only with `--seqtab_input`).
- `preprocessing/blast/`
  - `seqtab.txt`: all BLAST hits of all ASVs (only with `--seqtab_input`).
- `preprocessing/taxonomy/`
  - `<sample>.taxonomy.csv`: MICOM taxonomy table (ranks, `id`, `abundance`, `sample_id`) fed to the growth step.
  - `<sample>.annotation.tsv`: for each species, how many models of the database it matched.

</details>

Check `annotation.tsv` to see how much of a sample could be modelled; unmatched taxa are dropped.

### Growth

<details markdown="1">
<summary>Output files</summary>

- `growth/`
  - `<sample>__<medium>.zip`: MICOM growth results (`growth_rates.csv`, `exchanges.csv`, `annotations.csv`) for one sample on one diet.

</details>

### Merged results

<details markdown="1">
<summary>Output files</summary>

- `merged/`
  - `ezflux.growth.zip`: all growth results combined, loadable with `micom.batch.results.load_results`.
  - `ezflux.growth_rates.csv`, `ezflux.exchanges.csv`: the merged tables. `sample_id` is always `<sample>__<medium>`, also with a single medium.
  - `ezflux.production_rates.csv`, `ezflux.consumption_rates.csv`: metabolite production and consumption rates per sample.
  - `ezflux.import_niche.html`, `ezflux.export_niche.html`: UMAP of taxa by the metabolites they import / export (interactive, micom's `plot_exchanges_per_taxon`).
  - `ezflux.growth_rates.html`: growth rate of every taxon in every sample (interactive, micom's `plot_growth`).
  - `ezflux.found_fraction.csv`: per sample, the number and the abundance share of taxa found in the model database (from micom's build manifest).
  - `growth_rates_mqc.png`, `import_niche_mqc.png`, `export_niche_mqc.png`, `found_fraction_mqc.png`: static versions of the plots, as shown in the MultiQC report.

</details>

If a dataset is too small for UMAP, the niche plots contain a short message instead of a figure; use `--umap_n_neighbors` to tune the embedding.

The interactive HTML plots load their JavaScript (vega) from a CDN, so they need internet access when opened. The same plots are embedded in the MultiQC report as static PNGs, which also work offline. The found-fraction plot shows, per sample, how much of the community (by taxa and by abundance) has a model in `--micom_db`; samples below 50% abundance are poorly represented by the models.

### MultiQC

<details markdown="1">
<summary>Output files</summary>

- `multiqc/`
  - `multiqc_report.html`: a standalone HTML file that can be viewed in your web browser.
  - `multiqc_data/`: directory containing parsed statistics from the different tools used in the pipeline.
  - `multiqc_plots/`: directory containing static images from the report in various formats.

</details>

[MultiQC](http://multiqc.info) is a visualization tool that generates a single HTML report summarising all samples in your project. Most of the pipeline QC results are visualised in the report and further statistics are available in the report data directory.

The report has sections for the micom model database coverage, growth rates, and import and export niches (static PNGs from `MICOM_MERGE`). The pipeline has special steps which also allow the software versions to be reported in the MultiQC output for future traceability. For more information about how to use MultiQC reports, see <http://multiqc.info>.

### Pipeline information

<details markdown="1">
<summary>Output files</summary>

- `pipeline_info/`
  - Reports generated by Nextflow: `execution_report.html`, `execution_timeline.html`, `execution_trace.txt` and `pipeline_dag.dot`/`pipeline_dag.svg`.
  - Reports generated by the pipeline: `pipeline_report.html`, `pipeline_report.txt` and `software_versions.yml`. The `pipeline_report*` files will only be present if the `--email` / `--email_on_fail` parameter's are used when running the pipeline.
  - Reformatted samplesheet files used as input to the pipeline: `samplesheet.valid.csv`.
  - Parameters used by the pipeline run: `params.json`.

</details>

[Nextflow](https://docs.seqera.io/platform-cloud/reports/overview) provides excellent functionality for generating various reports relevant to the running and execution of the pipeline. This will allow you to troubleshoot errors with the running of the pipeline, and also provide you with other information such as launch commands, run times and resource usage.
